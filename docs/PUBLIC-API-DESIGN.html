Executive decision

Design three explicit surfaces: basic index access, compiled plugins, and disposable scripts. Keep Indexino as the final embedded facade; publish a small, separately versioned plugin API; and make .indexino.kts a JVM-only, read-mostly scripting layer over immutable snapshots. Keep Xodus, CLI, topology, parser implementations, and orchestration internal.

The facade is a boundary, not a public rearrangement of current classes. Both the CLI and embedded API connect through an internal local-runtime protocol; the workspace runtime owns IndexingCoordinator. Compiled plugins contribute durable analysis through a capability-based SPI. Scripts ask ad-hoc structural questions through a higher-level DSL; they do not receive the producer SPI or persistence handles.

Large-repository invariant Indexing IntelliJ Community, Android Studio, or another very large workspace once may be expensive. Opening the same state again must not be. The last complete snapshot becomes queryable immediately; a no-op refresh runs no analyzers, and an incremental refresh performs work proportional to changed inputs and their invalidation closure, not to total repository size. Freshness reconciliation may run beside queries, but it must never force a full rebuild merely because a client or daemon restarted. Each refresh analyzes one immutable capture of every discovered source: facts, content keys, source fingerprints, and the published generation must describe those same captured bytes. A concurrent edit may fail or defer to the next refresh, but must never publish a false-fresh generation.

Invariants

  • No public type mentions Clikt, Xodus, kotlinx.serialization, Kotlin PSI/compiler, producer, manifest, or topology implementation classes.
  • The CLI’s JSONL schemas and exit codes remain separate compatibility surfaces; the embedded API does not emit or parse CLI JSON.
  • Engine services accept internal typed inputs and a suspending progress sink; they do not know stdout, stderr, or ProgramResult.
  • Public callers see one logical IndexSnapshot. Shard count, storage engines, fan-out, routing summaries, and link-index implementation remain internal.
  • A workspace generation atomically pins one topology generation, an ordered set of immutable shard generations, and one compatible link generation. Queries never observe an unpublished mixture.
  • Client/session lifetime is not refresh lifetime. Disconnect, collector cancellation, and client close() release observation resources only.
  • Plugins receive final host-owned contexts and namespaced fact sinks—not Xodus, PSI, the host CoroutineScope, or arbitrary persistence handles.
  • Scripts receive immutable snapshots and ephemeral result sinks—not the plugin registrar or a persistent fact writer.
  • Index builds publish atomically from an internal staging location. Cancellation or failure never makes a partial store current and never overwrites a last-known-good index.
  • On-disk layout is internal, per-machine, and out of the worktree (user-local cache root). Existing pre-contract layouts are wiped/rebuilt; migration is a non-goal. The checkout must not gain an Indexino directory.

Local trust model

v1 is single-user and local. Any process running as the same OS user that can open the workspace endpoint may refresh, stop work, load configured plugins, or call shutdownRuntime(). There are no capability tokens, observer-vs-controller roles, or multi-tenant ACLs. The realistic abuse case is local denial-of-service against the index daemon (CPU, disk, cancelled work)—not remote compromise. Hardening beyond owner-only endpoint permissions is out of scope until an out-of-process untrusted-plugin story exists.
  • Plugin JARs and scripts remain arbitrary trusted code loaded only from explicit paths.
  • Canonicalize plugin/script paths and reject world-writable locations with a warning or hard fail in strict mode.
  • Do not invent a sandbox; document trust explicitly in CLI help and API KDoc.

The basic fact model must be richer than today’s CLI rows

A script such as “find usages of composable A whose content slot contains a usage of B” must not reparse source or depend on the selection plugin. The basic index therefore needs reusable structural facts: snapshot-local call-site IDs, source ranges, callee candidates, receiver, enclosing declaration, lexical parent call, and ordered arguments with source position, resolved name when known, value/lambda/trailing-lambda kind, range, and nested call IDs. Resolution uncertainty is represented explicitly with candidates and confidence; it is never hidden behind a false exact answer.

Android/CMP resource identity (definitions, variants/qualifiers, and R.type.name usages) is required before the first Central release but is deliberately deferred to slice S10 so early tracer slices can validate symbols, calls, plugins, and daemon lifecycle first. Compose decoration (ordered modifier chains, helpers/conditionals, confidence) ships as a compiled plugin over generic call/argument facts—not private PSI—after the SPI is proven by selection-context.

Basic fact schema version

Coordinate Core persisted structural facts carry an integer BasicFactSchemaVersion (start at 1). It is embedded in generation manifests, chunk keys, and plugin descriptors as requiredBasicFactSchema. It is not the product SemVer, not the plugin ABI, and not a public query field consumers must parse—though IndexStatus may expose it for diagnostics.
  • Bump required when a basic fact shape changes in a way that old chunks cannot be read or would silently mean something else (new mandatory call-argument fields, changed resource identity, altered symbol keying).
  • No bump for additive optional fields that readers tolerate, pure bug-fix recomputes that preserve meaning, or plugin-only namespaces.
  • On unsupported required version, the host rebuilds affected core chunks; plugins whose requiredBasicFactSchema is higher than the host’s fail at load with a clear diagnostic.
  • Plugin fact schemas remain separate per-plugin integers under the plugin ID namespace.

Future: provenance-aware links from resolved dependencies to source checkouts

Deferred, but preserve the seam A future source-link registry may connect an actually resolved classpath/native component to sources available elsewhere on disk. For example, an IntelliJ Community/Jewel index could link its resolved Compose Multiplatform component to ~/src/compose-multiplatform, then follow declared component edges to local Skiko and Skia source trees. Promotion path

throwaway script→compiled plugin→basic fact

Start an uncertain query as a script. Promote it to a compiled plugin when it becomes durable, expensive, shared, or needs incremental persistence. Promote only the broadly reusable primitive facts into the basic index; keep domain policy and audit semantics in plugins.

Entry point and lifecycle

  • Indexino is a final, closeable client facade; consumers cannot implement a library-owned interface.
  • suspend fun connect(…) is the primary entry (canonical path, lease, optional daemon spawn). connectBlocking is the CLI-friendly mirror. connect(IndexinoConfiguration) reserves an evolvable configuration boundary.
  • suspend fun snapshot(freshness: FreshnessPolicy) is the agent’s default verb: PUBLISHED pins the last complete generation immediately; AWAIT_CURRENT joins/awaits refresh for active scopes then pins. Prefer this over manual refresh+snapshot when the caller does not need a custom RefreshRequest.
  • The workspace runtime—not the client object—fixes the loaded plugin set and owns the supervisor, CPU/I/O/process budgets, watcher, durable refresh registry, stores, plugin classloaders, and child subprocesses.
  • Auto-refresh is the default runtime policy. Once a scope has been indexed or requested, relevant filesystem changes enqueue its next refresh without requiring an agent or client to ask.
  • close() is idempotent. It disconnects the client and releases its snapshot leases; it never implicitly cancels shared refresh work. Calls on that client after close fail with category CLOSED.
  • shutdownRuntime() is a separate, explicit shared-daemon operation for callers preparing to delete/move a workspace. It uses the same local-trust endpoint as other operations and must never be conflated with ordinary client close().
  • Prefer a lexical use { } scope per client session. Multiple clients for one workspace intentionally converge on the same runtime and refresh registry.

Configuration and requests

Configuration starts with a workspace Path and may add explicit plugin JAR paths, auto-refresh mode, runtime attach mode, and resource budgets (withMaxParallelism / withResourceBudget). Cache root defaults via env/XDG/platform; it is not a required configuration field. Never expose parser home, CoroutineScope, dispatcher, or automatic “load code found in this workspace” switch. Future optional settings are additive fluent methods or overloads—not defaulted constructor parameters.

Auto-refresh mode belongs to the shared workspace runtime, not to an individual client. The default is ENABLED. An advanced configuration may request DISABLED when launching a runtime for a throwaway checkout; an incompatible request must not silently mutate an already-running shared runtime. The active mode is visible in status. CLI exposes the same choice as --no-auto-refresh, while explicit refresh remains available in either mode.

Trusted code, explicit trust

Both plugin JARs and scripts are arbitrary in-process JVM code. Indexino does not claim a sandbox. Loading is explicit by path, configuration, or CLI flag; descriptors and script digests are reported; plugin dependencies are isolated; and scripts do not resolve network dependencies implicitly. A future untrusted-code story requires an out-of-process protocol and operating-system isolation.

At startup the JVM host reads and validates each plugin manifest before loading provider classes. Only after the target ABI passes does it create one isolated classloader per plugin dependency closure and discover IndexinoPluginProvider through ServiceLoader. The loaded set is frozen for the lifetime of the workspace runtime. v1 has no hot unload or replacement; restart the runtime to change plugin code or configuration.

Model shapes follow semantic closure

Avoid public data classes in stable APIs: their primary constructor, copy, and componentN methods make ordinary property evolution a broad binary and source change. Identifiers and value/request/result types are ordinary final classes with private constructors and @JvmStatic of(…) factories—not @JvmInline value classes (mangled member names are unreachable from Java; identifiers mostly live in collections/nullables that box anyway; factories can validate).

Mandatory structural equality. Every public value, request, query, and result type declares equals, hashCode, and toString (shown in the listing; Metalava omits java.lang.Object overrides from signature dumps). Enforced by detekt (package-scoped, opt-out for reference types: Indexino, IndexSnapshot, RefreshHandle, IndexinoException). Without this, refresh deduplication and Set/Map usage silently break.

Use sealed hierarchies for subtype sets closed within an API major. Prefer constant classes (private ctor + @JvmField constants) for values the engine produces (ArgumentKind, RefreshOutcome, ResolutionConfidence, SnapshotFreshness) so adding a case is not an exhaustive-when source break. Keep Kotlin enum class only for values the caller supplies (AutoRefreshMode, RuntimeAttachMode, FreshnessPolicy). Open-ended codes (warnings, check IDs) remain strings.

Public properties use stable JDK/Kotlin types or purpose-built domain types such as PluginId, SymbolId, CallSiteId, SourceFile, and WorkspaceRevision. Collections remain immutable snapshots. No public type exposes persistence, parser, or build-system implementation details.

WorkspaceRevision.fingerprint is an opaque digest of the complete ordered origin graph and topology state; callers compare it but never parse it. SourceOriginRevision.revision is the Git commit or equivalent source-control revision when one exists, while stateFingerprint is always present and also covers non-Git origins and working-tree state. expectedRevision records a parent gitlink or manifest expectation separately from the mounted child’s actual revision. Origins are returned in deterministic SourceOriginId order. SourceFile.path is normalized and relative to its origin; displayPath is diagnostic text only and is never an identity or lookup key.

Durable refresh and observation contract

A refresh is hot, shared, and owned by the workspace runtime—not by an observing client. Calling refresh(request) starts or joins one durable refresh. Disconnecting, closing a client, or cancelling an event collector only stops observation. The refresh continues until it publishes a complete snapshot, fails, or receives an explicit stop request.

A process-local library cannot outlive the agent process that loaded it. Cross-session continuation therefore requires a long-lived local Indexino workspace runtime, normally a daemon. CLI and embedded clients connect to that runtime; the engine remains reusable in-process for tests and integrations, but only daemon mode promises work will survive a client session ending.

Auto-refresh is the primary operating mode

Default on The watcher does not merely mark status dirty. For every previously requested/indexed scope, a relevant change is durably journaled and enqueues a refresh automatically. Agents normally query an already-current generation; they should not spend a tool call, latency, or tokens remembering to refresh first.
  • Runtime startup opens the last complete generation first, registers the watcher without a change-loss gap, then reconciles downtime. A missing or dirty generation is enqueued automatically.
  • Watcher bursts are debounced and coalesced by path and scope. A bounded maximum delay prevents a continuously changing checkout from postponing publication forever.
  • An event during an active refresh marks the scope dirty and contributes to exactly one successor refresh. It never starts a competing writer.
  • Auto and manual requests enter the same RefreshRegistry, resolve the same RefreshKey, share durable staging, and deduplicate when they target the same filesystem epoch.
  • A manual refresh(request) forces reconciliation even when no watcher event was observed. It is the recovery path for missed events, disabled auto-refresh, unusual generated inputs, and callers that require an awaited freshness point.
  • Auto-refresh derives the watch set from each active scope’s resolved source closure (plus topology/build/configuration inputs for those scopes)—not the entire origin mount. Events map to owning origin/shard and dependent scopes. Exclude VCS internals and the user-local cache root so publishing cannot self-trigger.
  • macOS: one native FSEvents stream (JDK 25 FFM, no JNA helper binary) with userspace path filtering—tree size is irrelevant. Linux: inotify over the scope closure; on ENOSPC degrade uncovered paths to periodic reconciliation and warn once at runtime (do not precompute feasibility against max_user_watches). Windows: stock JDK WatchService. No native code on Linux/Windows.
  • When watch coverage is incomplete (overflow, ENOSPC remainder, unwatchable root), freshness reports UNKNOWN for affected scopes until reconciliation proves currency. S7 must artificially cap the watch budget and assert an out-of-set edit is still caught by reconciliation.
  • A failed automatic attempt leaves the last complete generation queryable and status dirty. Retries are bounded/backed off; a new change or manual request may retry immediately without creating a busy loop.

DISABLED is an intentional low-footprint mode for one-off inspection of throwaway checkouts. It disables watcher-triggered scheduling, not persistence, incremental reuse, status, or manual refresh. Turning it off must never weaken freshness reporting: the published snapshot remains explicitly dirty or unknown until a manual reconciliation proves it current.

Workspace disappearance is a terminal, loudly diagnosed condition

Agent deleted my workspace A daemon must bind to the identity of the worktree it opened—not merely its path string. If that worktree is deleted, moved away, or replaced at the same path, the runtime transitions once to WORKSPACE_LOST, refuses all new refresh/query work, releases its resources, and exits. It must never recreate the workspace, recreate a cache or runtime endpoint under a replacement directory, or silently attach the old index to new filesystem contents.

At startup the runtime captures the canonical root, filesystem identity when available, Git common-dir and worktree identity when the primary origin is Git, and a local runtime marker backed by the global workspace/origin registry. It watches the root’s parent and performs bounded liveness probes because a watcher on a deleted root is not itself a reliable final notification. A confirmed missing root or identity mismatch is terminal. Permission denial, an unavailable network mount, or an indeterminate I/O error is reported as temporarily unavailable and retried; it is not misclassified as deletion.

Required shutdown sequence

  1. Atomically mark the worktree runtime WORKSPACE_LOST; reject new clients and scheduling.
  2. Emit one high-severity structured diagnostic and fail every active refresh/operation with non-retryable category WORKSPACE_LOST.
  3. Stop auto-refresh, watchers, maintenance, analyzers, and Bazel/Gradle subprocess trees through structured cancellation.
  4. Close client sessions, snapshots, stores, plugin/script resources, executors, and the workspace endpoint/lease.
  5. Abandon the deleted worktree’s staging manifest and remove its GC/current-generation reference. Immutable fact chunks shared with other worktrees remain valid and are reclaimed only by normal cache GC when unreferenced.
  6. Write a cleanup tombstone outside the deleted workspace, remove the endpoint, and terminate the daemon. Cleanup must not write through the vanished workspace path.
Loud diagnostic Connected embedded clients receive the terminal runtime diagnostic before disconnection; active refresh handles receive the same failure. CLI/RPC mode writes a prominent stderr message and structured machine event. The global workspace/origin runtime registry retains a tombstone so the next daemon-management command or attempt to use that canonical path reports that Indexino shut itself down because the workspace disappeared, and instructs the agent to run indexino daemon stop --project … or the embedded shutdownRuntime() operation before deleting a workspace next time. Client close() only disconnects and is deliberately insufficient. A detached daemon cannot inject text into an agent process with no live transport, so the persistent tombstone is required rather than relying on daemon logs alone.

Durable incremental work

Do not wait until the end to serialize all useful work. File analysis produces durable, immutable chunks keyed by source content hash, core fact schema, parser/analyzer version, plugin version and configuration, and relevant topology identity. A staged-generation manifest records completed chunks and remaining work. The complete generation becomes current through one atomic manifest swap; partial staging is never queryable as the current index.

  • A client disconnect wastes no work; the daemon keeps analyzing and publishes the generation.
  • An explicit stop or daemon crash preserves valid completed chunks and the incomplete staging manifest. A later equivalent refresh resumes from them.
  • If no indexed input changed, startup opens the published manifest immediately and returns UNCHANGED.
  • If inputs changed, only invalidated/removed files and dependent post-processing are recomputed; unchanged chunks are reused.
  • Changes to topology, parser versions, plugin schemas/configuration, or a fact dependency invalidate exactly the affected closure, not necessarily the entire workspace.

What a chunk is

Physical form (v1 decision) A chunk is an immutable content-addressed pack record (related analysis facts for a single analysis-key + content-key), stored as a file under the two-level fanout—not a separate Xodus environment per source file. Packing reduces filesystem block overhead at monorepo scale (~400k source files). Xodus (or equivalent) may hold generation-local indexes that reference chunk IDs. Put-if-absent installs a pack; readers open by content key.

Cache reclamation

Age is primary hygiene; quota is a backstop. Aggressive LRU that evicts soon-needed chunks would turn “zero-analysis reopen” into full rebuilds.

  1. Reference-based (correctness). Chunks reachable from any live current pointer, pinned snapshot lease, or resumable staging manifest are never reclaimed.
  2. Age (default). Unreferenced chunks and dead-workspace generations expire after ~30 days.
  3. Quota (backstop). Generous default; never evict below one complete generation per live worktree without an explicit force flag.
  • Registry entries plus a liveness sweep reuse the same three-way classification as WORKSPACE_LOST (confirmed-missing / replaced / temporarily-unavailable). Temporarily unavailable mounts are never reaped.
  • Reclamation is automatic in the maintenance scope—not on client disconnect. indexino status may hint when reclaimable bytes cross a threshold. Explicit CLI only in v1: cache status | gc | forget and daemon stop --purge. Not an embedded agent API.
  • GC race: grace window + re-verify reachability immediately before unlink after concurrent put-if-absent refresh.
  • last-used: recorded explicitly in the registry; never inferred from filesystem atime.

Cheap worktree forks now; true overlays later

A worktree fork must avoid source re-analysis, but v1 does not require a query-time base-plus-delta store. If branch B is created from a fully indexed branch A at the same commit, scope, analyzer/plugin versions, and configuration, B starts from A’s compatible generation and runs zero analyzers. B may create its own small generation manifest or materialize internal index metadata. The acceptance criterion is zero analysis—not zero bytes written.

If B differs from the nearest compatible cached generation, Git plus the worktree inventory identifies candidate paths; Indexino computes only their explicit invalidation/post-processing closure and reuses all other fact chunks. A and B publish independent generations and auto-refresh independently: editing B must not dirty A.

The shared cache is not one mutable cross-worktree index. Fact chunks are immutable and installed with atomic put-if-absent semantics; generation manifests and current pointers remain worktree-specific. Concurrent A/B refreshes may therefore publish independently without serializing every worktree behind one writer or exposing either worktree to the other’s partial state.

Deferred optimization A true zero-copy fork represented as an immutable base generation plus delta/tombstone overlays is a follow-up. It requires overlay-aware queries, deletion semantics, compaction, maximum chain depth, migration rules, concurrent ref-counting, and garbage collection across worktrees. Nothing in the v1 public API or generation identity may prevent that representation later, but v1 correctness and performance do not depend on shipping it.

Observation, replay, and backpressure

RefreshHandle.events() is an observation Flow, not the operation trigger. Each collector immediately receives the current refresh state, then future transitions; completed handles replay the terminal result. Cancelling or slowing one collector has no effect on the workspace job or other clients.

  • Lifecycle transitions, warnings, and the terminal result are ordered and retained in the bounded operation journal.
  • High-rate progress is conflated to the latest state per phase. A slow subscriber may skip intermediate counters but never a terminal result or warning.
  • await() waits for the shared terminal result without requiring event collection.
  • Recollecting events() observes the same refresh; it never starts another refresh.

Nested structured concurrency

Coroutines remain the orchestration model for parallel work at every level: the runtime may serve multiple clients while a watcher coalesces changes; one index build may scan many files; one plugin may fan out analyses and post-processing; maintenance and Bazel/Gradle calls run beside them. Every job remains a child of a runtime-owned refresh or maintenance scope. Global semaphores bound CPU, filesystem I/O, and subprocess concurrency so nested parallelism cannot multiply into unbounded work. Plugins receive managed execution services and cancellation, never the raw root scope.

Explicit stop

Under normal workspace liveness, only RefreshHandle.stop(), the corresponding CLI/RPC command, or explicit workspace-runtime shutdown cancels shared refresh work. Confirmed WORKSPACE_LOST is the sole safety-triggered exception. Stopping is idempotent and available to any connected local client; one observer cannot accidentally stop work merely by disappearing. Long CPU/blocking stretches still call ensureActive() at least per source file and between phases. Blocking subprocess work is interruption-aware and destroys the process tree on stop. Kotlin’s cancellation guidance explicitly requires checkpoints when work does not suspend for long periods.

Stopping an automatic attempt does not falsely mark the scope current and does not immediately spin up the same attempt again. It places that dirty epoch on retry hold until a new filesystem change, a manual refresh, runtime restart reconciliation, or an explicit auto-refresh policy transition. To pause all watcher-triggered work predictably, launch the runtime with auto-refresh disabled rather than repeatedly stopping individual handles.

Resource ownership

  • The workspace runtime owns worker executors, plugin classloaders, watchers, subprocesses, staging, and the refresh registry.
  • The client owns only its connection, handles, and pinned snapshot leases. close() disconnects and releases those leases; it does not stop shared refresh work.
  • RefreshCompleted means the generation manifest is committed and reopenable after daemon restart.
  • shutdownRuntime() and indexino daemon stop --project … are the explicit daemon shutdown operations (any local client that can open the endpoint). They checkpoint staging, stop child work, release the workspace lease, and leave the last complete generation readable.
  • A workspace-loss shutdown abandons only the lost worktree’s staging/refs, preserves shared immutable cache data, writes no path beneath the lost root, and exits after releasing every runtime resource.

Snapshots, checks, scripts, warnings, and failures

Query shape

Recommendation Make status and snapshot acquisition suspending. Basic snapshot queries return immutable QueryPage<T> results (items + pagination metadata), never raw storage cursors, Sequence, or a storage-backed Flow in the first release surface.

The current store implementation materializes prefix scans and sorts before emission. Public streaming would claim backpressure the engine does not have. Pagination is the v1 scale valve: callers pass QueryOptions (limit required for broad queries; offset or opaque cursor). Default limits are documented and generous enough for targeted agent queries; exceeding the host maximum fails with INVALID_REQUEST rather than attempting to materialize unbounded monorepo results. Define a total order for each query kind now (stable sort keys) so QueryPage.nextCursor / QueryOptions.after can be added later without reinterpretation. Offset pages remain O(n) over scan-then-sort stores; accepted for v1. A later opt-in streaming API would use a new name; it would not change QueryPage to Flow.

  • status() is cheap by default: manifest + last known freshness, no topology rediscovery. Freshness is a single SnapshotFreshness-aligned field—not three overlapping booleans (indexed/fresh/dirty). An explicit reconcile path (manual refresh / AWAIT_CURRENT) may rehash.
  • snapshot(PUBLISHED) immediately pins the latest complete published generation; it never waits for an active successor or exposes staging. snapshot(AWAIT_CURRENT) joins the durable refresh path first. freshnessAtAcquisition is fixed for the pin; the world may move on without updating that field.
  • After refresh(request).await(), a new snapshot() observes that completed generation. Existing snapshots remain pinned and deterministic.
  • findSymbols, findReferences, and findCalls are deterministic within a snapshot. Resource queries arrive in slice S10 and are absent from earlier experimental cuts.
  • Queries merge shard results through the pinned link/routing generation. Symbol/call IDs are opaque and generation-local (see Entity IDs). Source paths are always origin-qualified.
  • Duplicate FQNs across shards remain distinct candidates. Build/classpath precedence may rank or resolve them, but storage order never decides semantic identity.
  • Compiled plugins expose checks through a generic runCheck route keyed by PluginId and check ID. The host memoises check results per (snapshot generation, CheckRequest) so QueryPage offsets do not re-run the whole check; IndexinoCheckV1.run still returns a full List to the host. A plugin may publish a typed convenience wrapper in its own artifact.
  • File-scoped and prefix/FQN symbol queries are first-class: SymbolQuery.inFile, CallQuery.inFile, and name match modes (exact / prefix / FQN) on SymbolQuery.
  • selection-context query and result types belong to the separately published reference plugin, not indexino.
  • Returned lists and nested lists are defensive unmodifiable snapshots. Null means “not known/not applicable”; an empty page means “known to have no elements” for that window.
  • Concurrent queries on one open IndexSnapshot are allowed. Events from Flow collectors are emitted on host-managed dispatchers; collectors must not assume the caller’s thread.

Manifest ABI target and load rule

The JAR manifest contains one required SemVer target, for example Indexino-Plugin-ABI-Target: 1.3.0. This is the minimum plugin ABI the plugin was built to use—not a self-declared maximum range. Each Indexino release publishes its current plugin ABI and knows the ABI interval it implements. For the normal single-major case, a plugin loads only if:

Plugin ABI compatibility predicate
host.supportedAbi.contains(plugin.targetAbi)

// Equivalent while one ABI major is supported:
host.abi >= plugin.targetAbi &&
host.abi.major == plugin.targetAbi.major

Indexino’s product version, the plugin ABI version, the plugin’s own version, and its persisted fact schema version are distinct coordinates. An Indexino release records the ABI version and intervals it implements; the plugin manifest records the ABI target it needs. Maven artifact versions may move on the same release train, but they are not substituted for this compatibility handshake.

The plugin ABI starts at 1.0.0; it does not use SemVer’s conventional unstable 0.x exception. Breaking binary, source, or required behavioral changes increment the ABI major. Additive contract changes increment the minor; compatible fixes increment the patch. A plugin targeting an older minor therefore remains loadable on a newer host in the same major. If a future Indexino release deliberately carries adapters for multiple ABI majors, its supported interval set—not the current-version shortcut above—is authoritative.

Build-time guard Generate the manifest target from ABI metadata embedded in the indexino-plugin-api dependency used to compile the plugin—not from its Maven artifact version. Allow lowering it only after the plugin compatibility test kit proves the artifact links and runs against that older ABI. A handwritten optimistic target would otherwise defer incompatibility to class loading.
Generated host range Do not hand-maintain host.supportedAbi. Every stable plugin-API release adds an immutable, version-named Metalava signature dump. The publication task reconstructs the compatible lineage, verifies the current surface against that lineage, and embeds the derived current ABI and supported interval set into Indexino. The loader consumes only that generated metadata.

Plugin facts live under a plugin ID and schema version inside the staged generation. They publish with the core facts or not at all. A plugin upgrade either reads a compatible schema, runs an explicit migration, or invalidates and rebuilds its own namespace; it never interprets another plugin’s opaque bytes by accident.

Conceptual namespace: content-addressed packs under <cache-root>/chunks/… keyed by plugin analysis identity; generation manifests under <cache-root>/workspaces/<workspace-id>/ reference those packs. Shard and composite generation manifests reference those immutable chunks. The path is an internal storage illustration, not a public filesystem API.

Warnings

A warning is a non-terminal RefreshWarningEvent containing stable code, human-readable message, and optional origin-qualified source. Codes are strings rather than an enum so new warnings are additive. Messages are diagnostic, not machine contracts. Consumers branch on code and retain an unknown-code fallback.

Runtime lifecycle diagnostics use Indexino.diagnostics(), a replaying observation Flow independent of any refresh. CLI adapters always collect it and render ERROR diagnostics to stderr plus the machine stream. Embedded agents should collect it for the client lifetime. A terminal WORKSPACE_LOST diagnostic is delivered before the connection closes when transport is still available; the external tombstone covers the disconnected case.

Failures

IndexFailureCategory is a final value object with known constants, not an enum. Initial categories are INVALID_REQUEST, INDEX_NOT_FOUND, TOPOLOGY, STORAGE_BUSY, IO, PARSE, PLUGIN, SCRIPT, WORKSPACE_LOST, CLOSED, and INTERNAL. Each failure also has a stable string code, message, retryability flag, and optional cause.

  • A shared refresh reports failure as terminal RefreshFailed; all handles for that refresh observe the same failure.
  • Status and query functions throw final IndexinoException carrying the same IndexFailure. No public constructors—host factories only—so consumers cannot fabricate failures.
  • Unexpected throwables map to INTERNAL, retain the original as cause, and never require consumers to reference an internal exception class.
  • Cancelling events() or await() propagates CancellationException to that observer only; the refresh continues. Explicit stop produces RefreshStopped.
  • Adding or changing a documented thrown failure is a behavioral compatibility change even when the JVM descriptor is unchanged.

Kotlin-first, scoped Java usability

ROI rule. Pay for Java friendliness when the cost is an annotation or a type-shape choice; do not pay when it requires a parallel API surface.
  • Java-usable: all data, request, and result types—ordinary final classes, @JvmStatic factories, @JvmField constants, getters, JDK collection types, AutoCloseable.
  • Kotlin-only until an adapter artifact: suspend entry points and Flow observation. Documented exceptions: connectBlocking for process entrypoints; non-suspend script DSL mirrors (host-owned).
  • Keep @JvmStatic / @JvmField. Drop value classes. No @JvmOverloads as evolution strategy; no public default arguments (use overloads—Metalava MissingJvmstatic catches defaults).

API evolution policy

Declaration rules

  • Prefer immutable ordinary classes with private constructors and public factories when a model is expected to gain properties additively.
  • Consumer-implemented interfaces exist only in indexino-plugin-api, are explicitly versioned, and never gain abstract members after publication.
  • The plugin registrar and all operation contexts are final host-owned classes; new contribution kinds are additive registrar methods, not changes to an omnibus plugin interface.
  • Use sealed interfaces/classes when the subtype set is semantically closed for that API major. Adding a subtype is a source compatibility change and therefore waits for the next major or a new versioned hierarchy.
  • Use enums for genuinely closed sets. Persist names rather than ordinals; adding a constant follows the same source-compatibility policy as a sealed subtype.
  • Do not use @JvmInline value classes for public identifiers. Use ordinary final classes with private constructors, @JvmStatic of, validation, and structural equality.
  • Do not publish data classes in stable API artifacts. Generated constructors, copy, and componentN make property evolution disproportionately expensive. Enforced by detekt NoDataClassesInPublicApi.
  • Every public value/request/query/result type declares equals, hashCode, and toString. Reference types (Indexino, IndexSnapshot, RefreshHandle) opt out explicitly.
  • Host-constructed types that cross artifact boundaries use public constructors annotated @IndexinoInternalApi (error-level opt-in), not internal constructor.
  • Avoid public type aliases and inline function bodies that expose implementation dependencies; their targets or implementations leak into caller source and binaries.
  • Avoid default arguments on stable public functions and constructors. Add a new overload or fluent method while keeping old descriptors.
  • Do not use @JvmOverloads as an evolution strategy.
  • Never expose mutable collections. Copy inputs and return unmodifiable snapshots; document order for every returned collection.
  • Treat nullability, parameter names, generic arguments, exception behavior, event order, dispatcher ownership, and cancellation as compatibility commitments even when a bytecode checker is silent.

These rules align with Kotlin’s current backward-compatibility guidance, including the warning that adding a defaulted parameter changes the JVM signature and that manual overloads are the conservative evolution path.

Observation Flow as ABI

Flow and suspend signatures expose kotlinx-coroutines-core and Kotlin coroutine calling conventions. The implementation must apply java-library and publish coroutines on the api configuration so consumers compile without adding a hidden dependency. RefreshHandle.events() returns Flow<RefreshEvent> as a replaying observation contract; collection never owns or starts the refresh. Changing that return type to a callback, SharedFlow, or Channel is an ABI change, while changing observation cancellation to stop the shared refresh is a breaking behavioral change.

Normal path Indexino.connectBlocking(workspace) (or suspend connect) uses auto-refresh by default once S7 lands. 1. Force or join a durable refresh and observe it

Kotlin · progress collection
import dev.sebastiano.indexino.api.*
import dev.sebastiano.indexino.model.*
import java.nio.file.Path
import kotlinx.coroutines.flow.collect
import kotlinx.coroutines.runBlocking

fun main(): Unit = runBlocking {
    Indexino.connectBlocking(Path.of("/work/intellij-community")).use { indexino ->
        val scope = IndexScope.bazel("//plugins/devkit/intellij.devkit.compose:compose")
            .includingDependencies()
        val request = RefreshRequest.forScope(scope)
            .withPlugin(PluginId.of("dev.sebastiano.selection-context"))
        val refresh = indexino.refresh(request)

        refresh.events().collect { event ->
            when (event) {
                is RefreshStarted -> println(
                    "Refresh ${event.id.value} (${event.trigger.value})"
                )
                is RefreshProgress -> println(
                    "${event.phase.displayName}: ${event.completed}/${event.total ?: "?"} " +
                        (event.currentFile?.displayPath ?: "")
                )
                is RefreshChangesDetected -> println(
                    "Changed ${event.changes.changedFiles}; removed ${event.changes.removedFiles}"
                )
                is RefreshWarningEvent -> System.err.println(
                    "${event.warning.code}: ${event.warning.message}"
                )
                is RefreshCompleted -> println(
                    "Done: ${event.result.outcome.name} @ ${event.result.revision.fingerprint}"
                )
                is RefreshFailed -> error(
                    "${event.failure.category.value}: ${event.failure.message}"
                )
                is RefreshStopped -> println("Stopped; resumable=${event.resumable}")
            }
        }
    }
}

2. Disconnect without stopping, then rejoin

Kotlin · session-independent refresh
import dev.sebastiano.indexino.api.*
import dev.sebastiano.indexino.model.*
import java.nio.file.Path
import kotlin.time.Duration.Companion.seconds
import kotlinx.coroutines.cancelAndJoin
import kotlinx.coroutines.delay
import kotlinx.coroutines.launch
import kotlinx.coroutines.runBlocking

fun main(): Unit = runBlocking {
    val workspace = Path.of("/work/intellij-community")
    val request = RefreshRequest.forScope(
        IndexScope.bazel("//intellij.idea.community.main:IntelliJ_IDEA_Community_Edition")
    )

    val refreshId = Indexino.connectBlocking(workspace).use { firstSession ->
        val refresh = firstSession.refresh(request)
        val observer = launch {
            refresh.events().collect { event ->
                if (event is RefreshProgress) {
                    println("${event.phase.id}: ${event.completed}")
                }
            }
        }
        delay(2.seconds)
        observer.cancelAndJoin() // Stops only this subscription.
        refresh.id
    } // Disconnects the client; daemon refresh continues.

    Indexino.connectBlocking(workspace).use { nextSession ->
        val sameRefresh = nextSession.refresh(request)
        check(sameRefresh.id == refreshId)
        val result = sameRefresh.await()
        println("${result.outcome} @ ${result.revision.fingerprint}")
    }
}

val outerCalls = context.calls.find(
    CallQuery.to("ComposableA"),
    QueryOptions.page(500),

Owner decisions

Ratified during design review (do not re-litigate without cause).
  • Kotlin-first, scoped Java: data types Java-usable; suspend/Flow Kotlin-only pending an adapter artifact.
  • Drop @JvmInline value classes; ordinary final classes with of + equality.
  • Keep @JvmStatic / @JvmField.
  • Out-of-tree user-local cache; nothing under the worktree.
  • Metalava sole signature source; drop KGP abiValidation and japicmp.
  • Cross-version linkage fixtures are release-time only; forward fixtures stay in check.
  • JDK floor 25 everywhere (align with JBR 25.0.3 pin).
  • Borrow Jewel detekt rules (equality + API status), package-scoped with opt-out.
  • Watcher: one native integration, macOS only (FSEvents via FFM); Linux/Windows need no native code.
